# TUN 模式与分流规则

“tun模式”在本文对应 Clash TUN 模式，TUN 虚拟网卡负责的接入与 clash规则负责的出口选择需要分开。本文解释系统代理、透明代理入站、默认栈和规则资料的阅读边界，不提供完整配置模板，也不按模式名保证连接结果。

## 接入方式与出口模式不是同一组选项

Verge 文档把系统代理解释为修改操作系统的代理设置，程序需要采用这份约定。Clash TUN 模式则通过虚拟网络接口接管连接，两者描述数据怎样交给处理程序。规则、全局、直连是另外一组出口模式，不属于同一选择层。

规则模式依照配置匹配出口，全局模式使用手选节点，直连走本地网络。这个描述可以帮助辨认术语，但不表明某份实际配置已经命中哪条规则。本文没有读取配置或连接记录，不以模式开关代替实际结果。

FlClash 的功能表也分别列系统代理、Clash TUN 模式、规则分流和代理组。功能并列说明项目把它们视为不同项目，不允许把其中一个标题扩成全部其他设置的同义词。本文不从功能表猜各平台的菜单位置。

软件名称与内核名字同样分开。图形界面可能提供开关，内核文档解释参数，两份资料的主语不同。客户端存在某个入口，不意味着它全部采用内核参考页的默认值；这一点需要对应的预设说明。

[Clash Verge Rev 官方文档站](https://clash-verge-rev.github.io/) 对应客户端概念，[mihomo 官方文档站](https://wiki.metacubex.one/) 对应内核配置资料。本文没有将它们合并为一个已经核对的设备教程，也不提供用来覆盖现有配置的整份文件。

## 系统代理的限制按文档原意保留

Verge 的名词解释指出，系统代理依赖应用主动读取系统设置，不能代理 UDP。这个范围属于该接入方式的文档描述，不是本文对所有浏览器和应用逐项测试。某个具体程序是否采用设置，不能由本文没有记录的环境推断。

Clash TUN 模式的说明则列 TCP、UDP 处理，通过虚拟网络接口接入。它解释为何这两种方式不同，不提供任意程序都一定连接成功的保证。资源、配置、系统与远端条件没有因接口存在自动完成核对。

对于不读取系统代理的程序，文档将虚拟网卡列为对应接入思路。本文不从示例扩出游戏、容器或企业软件的完整覆盖表，也不写效果结论。没有具体应用资料时，不能把一个类型描述变成逐个兼容声明。

因此，“系统代理打开”不能直接改成“全部数据已按配置处理”，Clash TUN 模式的开关也不承担同样结果承诺。两项都是配置入口，需要实际环境记录才能描述执行状态。本文没有取得设备操作信息。

这种区分限于技术概念，不涉及规避监管、身份伪装或隐藏行踪的方法。系统设置的名字不会在本文被转换成这类结果。这里记录的是文档对象，而不是对任何网络环境的操作方案。

入站下的代理端口有 port、socks-port、mixed-port、redir-port、tproxy-port 等名称。本文只确认这些名字在文档中出现，不填默认端口，也不添加监听地址。字段列表不是可以直接运行的配置。

listeners 又有 HTTP、SOCKS、Mixed、Redirect、TProxy 及协议相关标题。某个名称能在这里找到，不能替应用确认它是否在界面开放对应选项。本文不把全部内核配置项称为图形应用功能。

## 默认栈冲突需要同时展示两个来源

截至 2026-10-22，官方页面显示 Verge 文档将默认堆栈写为 GVisor，mihomo 英文页则写默认 mips，以官方页面为准。两份默认文字不能由本文合成一个统一值，也不按名称大小写推断当前设备配置。实际安装版本没有在这里被读取。

mihomo 的参考中有 system、gvisor、mixed、mips 等选项。对 mixed，它解释 TCP 采用 system、UDP 采用 gvisor；对 gvisor，说明在用户态实现协议栈。这里只采用已取得的定义，不把描述延伸成跨设备优劣次序。

同一默认字段在不同资料出现差异，结论应保留来源和日期。本文不推断差异产生原因，也不据此判断某份资料是否已经失效。能够确认的是读取到的文字，不是某个实际连接正在使用的栈。

## 服务与防火墙说明分别对应进程和系统条件

Verge 服务模式安装并启动以后，服务进程负责启动内核，资料把非管理员身份启动 Clash TUN 模式列为用途。服务是独立后台进程，退出图形界面后仍可运行。本文不据此认为所有相关客户端都有相同服务安装方式。

Verge 文档还要求向防火墙放行 verge-mihomo 与 verge-mihomo-alpha。这里记录的是指定程序，不把要求改写成关闭整个防火墙，也不替其他平台生成同名文件。程序名与应用显示名不是同一栏。

mihomo 的参考另对 system、mixed 与防火墙条件作说明。它属于内核文档，不能省略上下文后当作任意软件的系统操作方案。本文没有在设备上设置放行，也不使用“已允许”之类状态描述。

服务是否启动、界面是否退出、内核是否运行和防火墙怎样处理，是不同的环境问题。只知道一个窗口关闭，不能由本文给出其余进程的当前状态。没有过程记录就不诊断关闭后网络表现的原因。

本文因此保留官方列出的对象和条件，不提供服务安装命令、不重写安全设置，也没有将配置说明当作已经执行的系统变更。所有实际状态仍需要来自对应环境的记录。

## FAQ

### Clash TUN 模式与全局是同一项吗？

前者涉及系统接入，后者属于出口选择。Verge 将它们写在不同概念中。

### 系统代理对所有程序都自动生效吗？

文档要求程序采用系统约定。本文没有逐个应用的覆盖记录。

### 默认栈应只写 GVisor 还是 mips？

两个来源分别给出这两个值。本文并列保存，不替实际设备选择答案。

### 退出界面就等于服务停止吗？

Verge 文档说明服务进程独立存在。窗口状态不能在本文代替进程状态。

### 防火墙说明就是要求全部关闭吗？

所引文字针对内核程序的放行。本文没有把它改写为关闭整个防火墙。

### DNS 两个模式的完整机制都已经确认吗？

当前资料只有选项与部分字段说明。本文不以字段名补出全部机制。

### 这里有可复制的完整规则文件吗？

没有，本文不提供模板。完整匹配次序也缺少可用原文，不冒充已经核对。

### 模式开了就代表订阅格式正确吗？

接入设置与配置输入是不同层。本文没有据开关状态确认实际文件可解析。
